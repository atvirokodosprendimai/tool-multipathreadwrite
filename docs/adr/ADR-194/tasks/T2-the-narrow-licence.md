## Ordered Steps

1. [S1] Write the failing test `TestANativeWriteLicensesOnlyTheLinesTheCallerSawAndWrote` through the locked writer path and see it RED. Cases, on a twelve-line file; a ranged read `A-B` serves `A` to `B+1` (ADR-161's line after):
   - read 3-4 (serves 3-5), write 3, then write 6: refused, the reason carrying the added clause; write 5: applies; write 4: applies;
   - read 3-8 (serves 3-9), insert two lines after 3, then write 11 (old 9): applies; write 12 (old 10): refused;
   - read 3-8, delete 4-5, then write 4 (old 6): applies; write 8 (old 10): refused;
   - read 3-6 (serves 3-7), replace 4-6 with one line, then write 5 (old 7): applies; write 2: refused; write 6 (old 8): refused;
   - read 3-11 (serves 3-12), one plan replacing 5 and inserting two lines after 8, then write 13 (old 11) and 14 (old 12): apply;
   - read 3-8, replace 4 with three lines, then write 8 (old 6) and 5-6 (the body): apply;
   - read whole, write 3, then write 9: applies, and the ledger entry is a whole `w`;
   - a plan whose `create` hunk makes the file: the ledger entry is a whole `w`, not `w|1-N`;
   - `--force` a write at 3 of an unread file, then write 4: refused; `--force` after a whole read of an older version: the same;
   - read 3-4 under the spelling `F` on a case-folding filesystem (skipped elsewhere), write through `f`, then write 6 through `f`: refused, write 4: applies;
   - read 3-4, one plan `@@ f 3 replace` and `@@ f - rename` to `g`: refused (a rename needs the whole file); with `--force`: applies, then `g` line 6 is refused;
   - after a write under Decision 2, `@@ f - unlink`: refused; after a whole read: applies;
   - after a write under Decision 2, `from=f:3` is refused and `occurrence=2` is refused until its earlier match is read, as today; a SEARCH/REPLACE write then `from=` of its body lines: refused (today: copied);
   - read 3-8 (serves 3-9), insert two lines before 3, then write 11 (old 9): applies; write 12: refused;
   - two files in one plan, one read whole and one read 3-4: each recorded by its own rule.
2. [S2] The carry. Mutants, each killed:
   - an insert's lines not added to the offset, so the insert case goes red;
   - a delete's lines not subtracted, so the delete case goes red;
   - a line inside a replaced range kept instead of dropped, so the shrinking-replace case goes red;
   - only the first hunk's offset applied, so the two-hunk case goes red;
   - the carry read from the plan's spelling instead of the observation apply judged, so the alias case goes red.
   [proof: mutation]
3. [S3] The writer's choice. Mutants, each killed:
   - always record whole (today), so the first case goes red;
   - record whole after `--force`, so the forced case goes red;
   - treat a created file as partial, so the create case's ledger assertion goes red;
   - key "created" on `FileResult.Created`, so the forced rename case goes red.
   [proof: mutation]
4. [S4] Run the whole suite and the contract. Each test or row that pinned the whole-file licence is moved with a line in the PR naming it and its record; any other failure stops the task. [proof: acceptance]
5. [S5] The words: `guide.go`'s sentence, core rule 2, AGENTS.md, README, BESTPRACTICES, `seen.go`'s comments, the contract comments, SKILL.md regenerated. [proof: acceptance]
6. [S6] Contract §335, through the built binary: read `f:3`, write line 3, then write line 5: exit 1, nothing written, the refusal carries the added clause; the pair: after a whole read, the same two writes exit 0. [proof: acceptance]
