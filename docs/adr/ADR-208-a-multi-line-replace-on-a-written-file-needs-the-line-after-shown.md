**Served-path change:** a multi-line `replace` that ends before the last line, on a file whose ledger record is whole and written-shaped (mrw wrote it, or a whole-file `--quiet` read licensed it), is refused unless a read has shown the line after the range in the file's current version: exit 1, nothing written, ADR-052's reason ending with the read to make (`mrw read --max-cols 0 PATH:S-N+1`, the range from the start of the edit through the line after it, when the path is one shell word, a description of it otherwise). It lands after that read, when the range ends on the last line, and when `mrw write --ast-grep … --rewrite` (or `mrw_write`'s `ast_grep` with `rewrite`) made the plan in the same call. A ranged `--quiet` read of such a file does not meet it. On `mrw_write` the refusal is the usual `isError` receipt with the failed hunk. With Decision 1a: the same refusal on a written-shaped record that is partial — a `search_replace`-only write's, a ranged `--quiet` read's, or a later-call `read --rewrite` plan's — when the line after was not shown at the current sha; and lines a `search_replace` write produced are not shown for `occurrence=N`, `from=` and `read --if-served` until a read shows them. The ledger's format does not change.

## Context

**ADR-052's rule.** A multi-line replace is refused unless the ledger covers the line after its range, because the closer a short range leaves behind sits on that line and the receipt cannot show it. The check is `needAfter` (`internal/apply/apply.go:1932-1936`): `haveObs && !obs.Covers(end+1, end+1)` for a numbered hunk, and for a quoted one (ADR-190) `tail == 0 && … && !(haveObs && recorded.SHA == shaBefore && obs.Covers(end+1, end+1))`.

**Why it does not fire on a file mrw wrote.** A file mrw wrote is wholly licensed (ADR-005): its record has `Spans == nil`, and `Covers` answers true for every line of a whole record (`internal/seen/seen.go:90-93`). The ledger also keeps what was shown since the write (`Shown`, ADR-118) and has the method that asks it, `ServedLine` (`seen.go:81-86`); `needAfter` does not call it. Neither does the numbered branch compare the record's sha with the file's: under `--force` the file-level "changed since" refusal is skipped (`apply.go:1430`, `:1444`) and the record kept is the old one (`:1464`), so its `Shown` can describe another version.

**Reproduced** on v1.93.0 (`18ffa49`; its `internal/apply` and `internal/seen` equal the reviewed commit `2ded135b`), 2026-11-20. `f.go` = `func A() {` / `\tif x {` / `\t}` / `}`:

| Record of `f.go` | Plan | Result |
|------------------|------|--------|
| created by `mrw write --create` | `@@ f.go 1-3 replace anchor="func A"`, body `func A() {` / `\ty()` / `}` | exit 0, a second `}` at line 4; the receipt's only sign is a `balance` row (`{ +1 → +0`) |
| read `g.go:1-2` (served 1-3, ADR-161) | the same on `g.go` | exit 1, `replace of 1-3 needs a served line after 3: read line 4` |
| created by `mrw write --create` | the same change as a `--format=search_replace` block | exit 0, a second `}` at line 4 |
| created by `mrw write --create` | the same change as a `--format=apply_patch` hunk (three `-` lines, three `+` lines, no context) | exit 0, a second `}` at line 4 |
| read 1-3, and not read | the same block | exit 1, the same refusal with ADR-190's hint |

The issue says the written case lands "with only a closer hint"; on this fixture there is no `closer` row, because the replaced range and the body both end in `}` (ADR-119's condition, `internal/apply/shape.go`), only the `balance` row.

**Which records are written-shaped.** `Written: true` is set by a landed write (`internal/writer/writer.go:108`, whole; a write whose every hunk was a quote records read-shaped spans instead, `:106`, ADR-190), a `read --sub` plan (`internal/read/read.go:996`, partial: the planned lines), a `read --rewrite` plan (`internal/read/rewrite.go:208`, partial: each span and the line after it, `:197`), and a whole-file `--quiet` read (probed: `mrw seen` says `no lines, and licensed the whole file`). A partial licence merged into a whole written record leaves it whole (`seen.go:846`).

**Which plans mrw makes.** `--sub` emits one single-line hunk per changed line (`internal/read/sub.go:59-64`), so ADR-052 never asks it for a line after. `--rewrite` emits one hunk per span of changed lines, which can be multi-line (`rewrite.go:189-196`). Both are marked `Computed` in `apply.Options`, and so are the foreign formats (`cmd/mrw/main.go:2331`, `internal/mcp/tools.go:1036`).

**Audit of the class**: *the records a multi-line replace can be judged against.* None (no ledger: every check skipped); read-shaped partial (`Covers` the spans: refused today when the line after was not served); read-shaped whole (shown everything); written-shaped partial (`Covers` the licensed spans, which for `--rewrite` include the line after); written-shaped whole (the hole). Only the last changes.

**Lines a search/replace write produced** (added 2026-11-20 with Decision 1a). A write whose every hunk on a file was a verified `search_replace` quote records that file as read-shaped, with spans that are exactly the lines it wrote (`internal/writer/writer.go:112-115`; the spans are each hunk's `newSpan`, `internal/apply/apply.go:783-789`; ADR-190). A read-shaped record has one set of spans, and `Covers` and `ServedLine` both answer from it (`internal/seen/seen.go:81-93`), so a line the caller wrote and a line a read showed look the same. Reproduced 2026-11-20 with mrw `v1.94.0-dev+aeb2e833`: `mrw write --create f.go` of five lines; a `--format=search_replace` block replacing `var z = 1` with `var z = 2` / `func B() {` / `\tif y {` / `\t}` / `}`; `mrw seen` shows `lines 5-9`; then `@@ f.go 6-8 replace anchor="func B"` with a body ending in `}` exits 0 and leaves `}` on lines 8 and 9, the receipt showing only a `balance` row. Line 9 was written by the caller's earlier call and never shown.
The ledger already has the shape this needs: a written-shaped partial record, `w<shown>|<licensed>` (ADR-161), licenses some lines and records which a read has shown. Its merge already keeps a showing apart from a licence: a read at the same sha adds its lines to the shown set; a licensed-not-shown record (a `--quiet` read, a plan) adds to the licence only; a whole-file `--quiet` keeps the shown set; a record at another sha replaces the old one (`seen.go:844-870`). What the ledger cannot do is tell a `search_replace` write's licence from a `--quiet` read's or a plan maker's: all three are licensed and not shown. A first draft of Decision 1a kept that difference with per-line provenance and a v7 format; two challenges found it leaking where provenance is lost or split — a later one-line write at a new sha, a second spelling's record, an in-checkout `--root`, and v6 records whose merge had already copied bare spans into a shown set (`seen.go:870`) — each needing more machinery (History). Decision 1a drops the difference instead.

## Existing Primitives Audit

- `Observation.ServedLine` answers "shown since the write" for a written record; ADR-118's `occurrence=` check (`apply.go:1683`) and the `from=` check (`fromcopy.go:246`) already use it.
- The quoted branch already binds the record to the file's sha; this record adds the same binding to the numbered branch, for this case.
- `staleRemedy` (`apply.go:2759`, ADR-203) builds the read command a refusal names, with `--max-cols 0`, so a line cut by `MRW_MAX_COLS` is read whole and licensed.

## Decision

1. **On a record that is whole and written-shaped, the line after is met only by a showing in the current version.** In both branches of `needAfter`, when `obs.Written && obs.Whole()`, the condition is `recorded.SHA == shaBefore && obs.ServedLine(end+1)`. Every other record is judged as today, the no-observation path included, except the written-shaped partial records Decision 1a adds.
1a. **(2026-11-20) On any written-shaped record, whole or partial, the line after is met only by a showing at the current sha.** Decision 1's condition, `recorded.SHA == shaBefore && obs.ServedLine(end+1)`, applies whenever `obs.Written`, not only when the record is also whole.
    - *A `search_replace`-only write is recorded written-shaped*: `w|<the lines it wrote>`, licensed and not shown, in place of today's read-shaped spans. Its lines stay licensed for an edit (ADR-190 Decision 1); they count as shown only once a read shows them.
    - *So three licences no longer meet the line-after rule without a showing*: a `search_replace`-only write's (the gap), a ranged `--quiet` read's (ADR-161 Decision 10), and a `read --rewrite` plan's written by a later call (ADR-161 Decision 3; T1's row `partial_written_licence` flips to refused). All three are licensed-not-shown, and the ledger cannot tell them apart. Refusing the last two costs a read of the line after, and is consistent with ADR-208's premise: a line nobody was shown does not show the closer.
    - *Unchanged:* Decision 3's exemption (a same-call `--rewrite`, whose plan maker licensed the line after); ADR-190's verified kept tail; Decision 4 (`--force` does not waive it); Decision 5's remedy (for the repro, `mrw read --max-cols 0 f.go:6-9`); a read-shaped record, which holds only lines a read served.
    - *What follows through `ServedLine`*: lines a `search_replace` write produced are not shown for `occurrence=N` (ADR-118: an `occurrence` above 1 is refused while an earlier match is such a line, single-line hunks included), a `from=` copy (ADR-167, which Zy limited to lines shown) or `read --if-served` (ADR-179: it serves the lines instead of answering by reference, `internal/read/read.go:889`) until a read shows them. That goes past the question Zy answered and is named for Zy.
    - *Spellings and roots*: the line after is judged as T1 judges it on `main` (`945654ef`, #745): across every spelling of the file the ledger holds and the root can see, counting another spelling's record only when it describes the current sha (`aliasIndex.records`, `servedAnywhere`, `internal/apply/apply.go`), so a showing under another visible spelling counts and a `--quiet` record under one hides nothing. The remedy keeps the root: `mrw --root DIR read --max-cols 0 PATH:S-N+1`, or a description of that read when the root or the path needs quoting (`staleRemedySpan`). On `mrw_write` the refusal carries the kind `line-after` (`internal/refusal/refusal.go`). Two limits stay, stated: an in-checkout `--root` sees only keys under its prefix (`internal/seen/checkout.go:28`), so a record under a spelling outside it is not consulted; and a write with `--force` and no visible record skips both the unread refusal and this rule, since there is no observation to judge (`haveObs`), as ADR-052's rule always has. Closing the second would refuse `--force` on unread files, which `--force` exists to allow.
    - *Format and migration*: none. `w<shown>|<licensed>` is ledger format v6, which every mrw since ADR-161 reads, and an older mrw reads a v6 ledger a newer one wrote.
    - *Residual window, stated plainly, per ledger key and sha*: a `search_replace`-only write recorded by an mrw without T2 — before the upgrade, or after it by an older binary sharing the v6 ledger — is read-shaped and meets the line-after rule by `Covers`. A T2 write that leaves that key's sha unchanged merges into it and copies its spans into the shown set (`seen.go:859`); a same-sha write over a written record whose shown set was already filled that way keeps it (`seen.go:857`, `:866`). The window closes for a key when a write changes its sha (the record is replaced, `seen.go:844-846`), when that key is read whole (the read replaces the record for its key), or when `mrw seen --forget` empties the ledger. Closing it outright would need a format bump and a reset of every v4 to v6 ledger, which is not proposed.
2. **The skips stay.** A range that ends on the last line needs no line after; a single-line replace is unchanged.
3. **One plan source is not judged by it: `--rewrite` in the same call** (`mrw write --ast-grep P --rewrite R`, `mrw_write`'s `ast_grep` with `rewrite`). Its span is the match mrw found, and the plan maker licenses the line after each span it computed (`rewrite.go:197`). `apply.Options` gains the fact that a plan came from that source; `Computed` keeps its meaning for ADR-200 and ADR-203. A plan printed by `mrw read --rewrite` or `mrw_read`'s `rewrite` and written by a later call is judged. `--sub` needs no exemption. Foreign formats (`--format=search_replace`, `--format=apply_patch`) are judged: the probe shows the hole there too.
4. **`--force` does not waive it**, as ADR-052 says, and cannot meet it with a showing of another version.
5. **The refusal names the read**: on such a record, ADR-052's reason ends with the read `staleRemedySpan` names: a command to paste, `mrw read --max-cols 0 PATH:S-N+1` (the range from the start of the edit through the line after it, under the plan's own spelling, since the ledger is per spelling; `mrw --root DIR read ...` when the command line named a root that is not the working directory), when the path is one shell word, and a description of that read otherwise (a path such as `a b.go`, or a single letter).
6. **The words.** `AGENTS.md` (rule 4's sentence on the line after), `README.md`'s neighbour-licence bullet and the full instructions (`internal/guide/guide.go`, the sentence "A file mrw just wrote is wholly known …") each say: `on a file mrw wrote, a multi-line replace that ends before the last line also needs the line after it shown since the write`.

## Alternatives Considered

- **Refuse only when the body ends in a closer the next line repeats** (ADR-119's `closer` condition). Rejected: it reads target syntax mrw does not model, and the probe lands with no `closer` row.
- **Licence the line after automatically by echoing it in the receipt.** Rejected: an echo after the write cannot stop the write; `--echo-pad` already exists for that.
- **Apply `staleMarks`' predicate whole: `Force` and every `Computed` plan exempt.** Rejected: it leaves the `search_replace` hole the probe shows, and ADR-052 already refuses to let `--force` waive the line after.
- **`ServedLine` alone, without the sha.** Rejected: under `--force` the record kept can describe another version.
- **Leave it.** Rejected: the closer guard is off on files the caller has just written.

## Consequences

- **Positive:** the closer guard holds on files mrw wrote, for native plans and foreign formats, as it already does on files the caller read.
- **Negative — the cost:** a second multi-line replace on a file mrw just wrote, or after a whole-file `--quiet` read, needs the line after the range shown first: one `mrw read PATH:S-N+1`, which a ranged read of the lines being replaced already serves (ADR-161); or, for a `search_replace` block, a REPLACE side that ends with the SEARCH side's last line (ADR-190's kept tail). A `read --rewrite` plan written later on a file mrw had written needs the same read. How often the refusal will fire is not measured; no existing count prices this shape.
- **Negative — Decision 1a's cost:** a multi-line replace whose line after a `search_replace` write produced, or a ranged `--quiet` read or a later-call `read --rewrite` plan licensed, needs that line read first: one ranged read, which the remedy names. A `from=` copy or an `occurrence=N` count over lines a `search_replace` write produced, and `read --if-served` for them, need a read too. No format change, no migration, nothing re-read on upgrade. Unmeasured, like the rest of this record's cost.
- **Neutral:** single-line replaces, inserts, deletes and ranges ending on the last line need no line after, as before. With Decision 1a an `occurrence` above 1 can be refused, and `read --if-served` can serve lines it used to answer by reference, where a `search_replace` write produced the lines involved.
- **Amended 2026-11-20** (go-reviewer of #745): an ordinary `apply_patch` hunk with trailing context compiles to a multi-line `replace` (`1-4 replace`), so on a file mrw wrote it is refused until the line after it is read; that is ADR-052's rule applied as written, and a `--format=apply_patch` plan needs the same read of the line after (`mrw read PATH:S-N+1`) as a native one. The read the refusal names runs from the start of the edit through the line after it (`F.go:1-4`), under the plan's own spelling: the ledger is per spelling, so a read of the line after alone, made under a case-folded name or a link, left a partial record the retry refused again.
- **Amended 2026-11-20, second review of #745:** the showing is judged over the file, not the spelling: a quiet read through a link or a case variant records a partial record under that spelling that used to cover the line after and hide the whole written record under the real name, so the rule consults the record of every spelling of the file (`os.SameFile`) and applies to the file if any of them is whole and written; the line after is shown when any spelling's record shows it, and `occurrence=` counts matches shown under any spelling, so a read the remedy asked for under an alias keeps an earlier showing. The read the refusal names carries `--root DIR` when the command line named a root that is not the working directory, as ADR-203's does. Over MCP the refusal (kind `line-after`) names `mrw_read` of the range through the line after, and, when that line is already served and not acknowledged, the checkpoint ids (`nameTheAck`).
- **Amended 2026-11-20, issue #753:** what is printed as a command is judged per platform and for every shell mrw meets, Git Bash included. A path or root of letters, digits, `.`, `_`, `-` and `/`, with a `~` that is not its first character, is commanded; on Windows a drive root (`C:\Users\x\r1`) and a relative path with backslashes are commanded in their slash form (`C:/Users/x/r1`), which cmd, both PowerShells and Git Bash run and Go reads as the same directory, since Git Bash eats a backslash. A UNC root and one with a leading separator (MSYS rewrites them), a space, a metacharacter and a word PowerShell reads as a number (`1.10`, `0x10`, `007`, `2kb`) are described, and the description names the file and the root as written, single-quoted (`a read that shows lines 1-4 of 'F.go' under the root 'DIR'`; Go-quoted only where a control byte or a quote forces it). The same function serves ADR-203's stale-number remedy.
- **Amended 2026-11-20, review of #755 (issue #753):** on Windows the command is further narrowed to what Git Bash leaves alone: a drive path (`X:/…`, a Windows path already) or a relative one with no `//` and no component MSYS maps to its own (`dev`, `tmp`, `usr`, `bin`, `etc`, `home`, …), so `_/dev/null` is described; a command longer than 8,000 characters (cmd.exe stops at 8,191) is described there; any one word that starts with a digit, or a dot and a digit, is described, since PowerShell's numeric grammar (`1.e2`, `5.`, hex, binary, exponents, suffixes) is wide and not followed; and a description Go-quotes a name that holds a control or format character (U+2028, U+2029, U+0085, a bidi or zero-width mark), a quote, or bytes that are not UTF-8. The tests run the remedy as printed, root included.

## Out of Scope

- A closer above the body (a short START), which the line after cannot show (permanent: boundary: ADR-052 chose the line after; a line before is a different miss, `internal/apply/apply.go:1922-1923`)
- A read-shaped record kept under `--force` after the file changed, outside Decision 1a (permanent: boundary: its spans are judged by `Covers` as today; ADR-052's `--force` rule for a partial observation is unchanged; Decision 1a binds the showing of a quoted write's lines to the sha, and nothing else changes)
- Records an mrw before Decision 1a wrote for a `search_replace`-only write, and the shown sets a merge already copied from them (permanent: boundary: rewriting them needs a format bump and a reset of v4 to v6 ledgers; the window closes on the file's next write, a whole read, or `mrw seen --forget`, and Decision 1a states it)
