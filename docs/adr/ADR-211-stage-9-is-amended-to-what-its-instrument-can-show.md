**Challenged before acceptance**, 2026-11-20, on `d4cec9d2`: Codex gpt-6.2-sol at xhigh, AMEND, ten required amendments and corrections to this Context, each checked against the code before it was applied. A null exposure would mean the agents were told not to and were not forced to.

A refusal never sits beside a landed write in M: ADR-203's failure fails the plan, and the text receipt prints `NOTHING WRITTEN` before it looks at `--dry-run` (`cmd/mrw/main.go`, `reportMode`).

- **B6, spend before T6.** `bench canary` has no dollar stop and runs A and B once per model, eight attempts across the four canaries, not ADR-206 Decision 8's "four each"; it writes no per-attempt receipt, so the run's `spendStop` cannot see its costs (`canary.go`); nothing checks the smoke's figures; the caps come from October tasks, not two-site ones.
- **B7.** T6 pays all six arms, then verifies. A run that ends exit 3 on its last attempt, its figure crossed, still passes `bench verify`.
- **B8.** T6's fence reads from `RESULTS.md` only the transcripts path.
- **B9.** An unpinned arm accepts another model's canary, and a test expects that (`internal/bench/stage9_test.go`, "a run that pins nothing checks no model"); `canary.json`'s `model` is the requested name, not what an attempt's init line reported; a receipt's `init_model` is recorded and never compared.

## Decision

1. **The claim is narrowed.** Stage 9 reports what each arm spends per exact reference completion within budget on dictated edits, M against A, by class. N is a negative control: expected to match M; a difference is reported as a difference between the two builds, not as the hazard. The pilot draws no conclusion about whether a number-only edit goes wrong when nothing refuses it. The hazard question moves to a `docs/adr/BACKLOG.md` entry that needs tasks whose second edit depends on a fact that exists only after the first write lands.
2. **One gate survives, per direction.** The Stage 9 entry registers a powered stage only when, for M against A on single-site or on batch, the interval of the spend ratio excludes 1 on both models and on the same side of 1. On opposite sides it is reported as the models disagreeing and registers nothing. M against A is also printed on follow-on and control, and gates nothing there. M against N is printed on follow-on and control as the negative control, and gates nothing. The M-against-N gate, the exposed-and-outside gate and the floor of 3 exposed follow-on tasks are withdrawn with the hazard question.
3. **N's log is written only by an event, beside the state home.** The patched writer appends to the log only after a landed write that holds an exposed hunk, to `stage9-exposed.jsonl` in the parent directory of `$XDG_STATE_HOME`; the bench sets that variable to `<scratch>/state` for every mrw configuration, so the log is the runner-owned `<scratch>/stage9-exposed.jsonl`, deleted with the scratch. A write with no exposed hunk touches nothing, so N and M act alike up to the first write M would have refused. With `$XDG_STATE_HOME` unset or relative, or on any failure to create, open, write or close the log, the write's result is unchanged and one stderr line follows it, `mrw: stage9 log: <what failed>`; that line can appear only on a write M would have refused. This takes a routine signal out of the state home; it is not isolation: the scratch directory is the agent's `TMPDIR`, and an agent that lists it after an exposed write can find the file. That N's plan lands with its siblings where M's is refused whole is part of the intervention and is in the report's limits.
4. **The runner keeps the log.** `bench run --keep-scratch-file NAME` takes one file name, no separator, in the attempt's scratch directory, opens it through a root on that directory under `keepStateFile`'s rules (a regular file, not a link, the file opened the one examined, at most the kept limit), and copies it to `<attempt id>.kept` before grading and before the scratch is removed; the receipt records `kept_scratch_file_sha256`, a refusal is a `scratch:` note in `kept_note`, `run.json` records `keep_scratch_file`, `bench verify` checks the kept file against its receipt, and the flag is refused beside `--keep-state-file`. N's runs pass `--keep-scratch-file stage9-exposed.jsonl`, and ADR-206 T5 and T6 require that value and no `keep_state_file`. ADR-206 T2's table and test change with the patch in the same task.
5. **Exposure has the states the evidence can tell apart.** A *write call* is a Bash call `MENTION` matches; it is *read* when it is one simple write command whose result is present, non-empty and shows no clipping the parser can detect: no host truncation marker anywhere in it, and a receipt that ends in its summary line. Otherwise it is *unattributable*, and nothing in its result is counted, so a clipped plan's refusals can never read as a lone failure.
   - N: an *event* is a kept-log line that is a JSON object with exactly the keys `path` (a non-empty string), `op` (`replace`, `delete`, `insert-after` or `insert-before`), `start`, `end`, `first_unshown` (integers, 1 ≤ `start` ≤ `first_unshown` ≤ `end`) and `sha_before` (64 lower-case hex digits). `exposed`: at least one event. `not seen`: no kept log, no `scratch:` note, and every write call read with no `mrw: stage9 log:` line in it. Otherwise `unknown`: a `scratch:` note, a log line that is not an event, a `mrw: stage9 log:` line, or an unattributable write call, with no event. No signal the runner owns can say capture worked when nothing was logged, so `not seen` is not a measured zero, and the report says so. An exposed attempt that also meets an `unknown` condition is flagged, and its hunk count is a lower bound.
   - M: an ordinary validation refusal is a `FAIL` row of a read write call's text receipt, or a failed hunk of its `--json` receipt, whose reason is ADR-203's; the same words anywhere else in a result, a quoted imitation included, are not one. Each is split by kind: on a dry run (the invocation carries `--dry-run`, or the JSON receipt `dry_run: true`), the only failed hunk of its plan, or beside another failed hunk. `exposed`: at least one. `not seen`: none, and every write call read, each a complete receipt that shows no refusal. `unknown`: none, and an unattributable write call. As in N, an exposed attempt that also has an unattributable write call is flagged, its count a lower bound.
   - `unknown` is its own column and in no rate's denominator; M's and N's counts are printed side by side and never divided.
6. **The cost statistic is named for what it is and reconciled over the stop's receipts.** It is "CLI-reported cost of terminal graded attempts per exact reference completion within budget, on tasks graded in both arms". Per run, the receipts are the ones the runner's spend stop sums (`spendStop`, `internal/bench/pins.go`): the `*.receipt.json` entries directly in the run directory and directly in its `side/` directory, no deeper, their costs compared in rounded millionths as the stop compares them; a receipt anywhere deeper is refused by `gate` and `count`, not summed. Each falls in exactly one bucket: *terminal graded* (the receipt `walk` picks, not an exclusion, a successful replacement included), *terminal excluded* (the picked receipt is an exclusion, or its `bin/mrw` changed during the attempt, Decision 7), *superseded* (a receipt a replacement followed) and *stray* (reached by no chain). Each bucket prints its known USD and its count of missing costs; the four sum to the stop's total and missing count, or `count` refuses. Per comparison, the statistic's spend plus the class's unpaired terminal graded spend is the arm's terminal graded spend in that class, and both are printed, known USD and missing counts, also when the comparison is INSUFFICIENT. The report also prints, per arm and class, the attempts with slipped writes, and says that one repeat leaves each task one observation per arm.
7. **The run's identity is fixed at close.** Each receipt whose attempt captured a transcript records `transcript_sha256`, the SHA-256 of the bytes the runner read back after closing it; a setup failure before the transcript was opened leaves the key absent. `count` requires the key on every graded attempt and refuses a transcript whose hash is not its receipt's, so M's and N's transcripts, which share stems, cannot be swapped. `count` reads the registered plans from a committed file — `bench/stage-9/plans.json` for the pilot, `bench/stage-9/smoke-plans.json` for the smoke, one code path — and refuses run directories that are not exactly those plans. `mrw_instructions_sha256` leaves `MAY_DIFFER` and is checked on its own: absent in A, present and equal in M and N, and pilot.md's. `MENTION` recognises `mrw` followed by any flags before `write`. An attempt whose `bin/mrw` changed during it (`mrw_sha256_after`) is `missing`, named in the report, and its spend stays in the reconciliation. A test holds the runner's existing refusal of a spend-stopped directory re-invoked with its own figure: exit 3 and no new `.started`.
8. **The model is the one observed.** `canary.json` gains `init_models`, per configuration the model its attempt's init line named; a configuration whose init line names none, or a canary whose configurations name different models, fails the canary. Every run, pinned or not, takes only a canary whose `model` is one it runs and whose profile is its own; the earlier "a run that pins nothing checks no model" is withdrawn. ADR-206 T5 records `init model <model>: <observed>` in `pilot.md`, the one value all of that model's canary configurations reported (two canaries of one model that disagree stop T5 for Zy), and both `gate`, at each run step, and `count` refuse a graded receipt whose `init_model` is absent or not that value, so a wrong model stops the stage at the step that ran it. The requested alias is recorded beside the observation and never compared with it.
9. **Every paid step is gated before the next starts.**
   - `bench canary --max-spend USD` sums the costs the canary has recorded before each configuration's attempt and after the last; at or over the figure, or on any null cost, it ends with exit 3 and still writes `canary.json`, which records the applied figure as `max_spend_usd`, `pass: false`, its costs and the reason under `problems["spend"]`; an interrupted canary writes it the same way under `problems["interrupted"]`. Figures: $0.75 for each Opus canary and $0.25 for each Sonnet one, $2 in all; an even $0.50 would stop an Opus canary whose two attempts cost the $0.25 each that ADR-206 Decision 8 allows. Like a run, a canary can pass its figure by one attempt.
   - The smoke is registered in `smoke-plans.json`: tasks `s9-pylint-logging-too-many-args-confidence` and `s9-requests-help-information-rename` in all six smoke runs, figures $0.80 for each Opus arm and $0.40 for each Sonnet arm, $3.60; and a probe, Sonnet A on the same two tasks with its own `--max-spend 0.01`, whose exit 3 and stop line on stderr are kept. Before T6, each arm's smoke cost per graded attempt times its planned attempts must be under its figure, or T6 waits for Zy. The smoke's two tasks are a follow-on and a control task, so its projection for A and M says nothing of single-site or batch costs; T6's per-arm gate bounds those.
   - `bench_stage9.py gate` checks one step's evidence: the `bench` exit status, recorded in `<directory>.exit` beside the step's directory, 0; the registered plan; every `.started` with a receipt, and the receipts exactly the planned attempts and the replacements owed, none stray; each kept diff and kept file matching its receipt; known spend under the figure with fewer than three missing costs, the runner's own rule; every graded receipt's `init_model` the observed value; for a canary, a pass, `max_spend_usd` its registered figure, no null cost, and `init_models` for each configuration, equal across the model's two canaries and to `pilot.md`'s. A run step starts at its earliest `.started`, and every receipt in it, replacements included, must have one; a canary starts at its `canary.json` `started`. The gate prints the step's clearance with its time, which is appended to `pilot/gates.txt` (the smoke's to `smoke/gates.txt`); it refuses a step that starts before its predecessor's recorded clearance, and a fence replays the gates against those recorded times, never the time of the replay. The first refusal stops the stage.
   - Order: Opus N, Opus M, Opus A, Sonnet N, Sonnet M, Sonnet A. N goes first in each model because it is the cheapest arm and the one with a patched build, and the two N runs are not adjacent.
10. **No dollar before a free rehearsal.** `bench/stage-9/instructions.txt` is committed first, byte-equal to `mrw-m instructions`. Then on the pilot Mac, from a clean checkout at the revision `pilot.md` will name and on the day of the canaries, `bench/stage-9/rehearse.sh` runs each check and writes `docs/bench/stage-9/rehearsal.md` with the command's real exit code: ADR-206 T2's build test and the corpus oracle test, each run and not skipped; a clean bench build whose revision carries no `+modified`; a hash over the 48 tasks' definitions and reference patches; the four canaries and the six registered plans, every task of every list, run with a stub agent and no model, the gate between steps, the stub making one exposed write in N; `count` and `report` on that output, with the stub's N event counted as `exposed`; and the fixture test of T5's and T6's fences. The record names its date, revision and input hashes, and T5 refuses one that is not `pilot.md`'s. After the smoke, `count` runs on the smoke's own output with the smoke plans before T6 starts.
11. **The two bench defects found on the way are fixed with it.** A check-coupled task's package tests run with the package's `_test.go` files as the base has them: each base file restored, each file the agent added removed (#709). Diff statistics and slipped writes are taken before grading, the diff statistics in an index of their own under the scratch, a copy of the tree's as `keepDiff` makes, so `git add -A` never touches the index the oracle reads; a file the grader creates is in neither, a file the agent created is in both, and the oracle still sees the agent's untracked files as untracked (#710).
12. **Spending again needs Zy's word.** The go-ahead of 2026-11-20 ("and then run paid test") was given for ADR-206 as it stood. After this record is accepted and its tasks are done, T5 waits for Zy to say so again.

## Alternatives Considered

- **Keep the hazard claim and add tasks now.** Rejected for this pilot: new tasks reopen ADR-206 T3 and its reachability check, and the dictated-edit cost comparison stands on its own.
- **Drop arm N.** Rejected: as a negative control it is what shows the two builds behave alike where the refusal never fires.
- **An empty log on every landed write, kept outside the state home, as the sign that capture worked.** Rejected: N would then differ from M on writes M lands too, before any refusal would have fired, which ADR-206 Decision 10 names as what would make it wrong.
- **Hide the N log entirely by writing it from the bench, not mrw.** Rejected: the bench cannot see which hunks the engine would have refused.
- **Verify all six arms at the end.** Rejected: it pays for five arms after the first one is known bad.

## Consequences

- **Positive:** the pilot's report can only say what its instrument measures; no money is spent on a fence, a gate or a parser nobody ran; N stays indistinguishable from M until a write M would refuse.
- **Negative:** the hazard question, which motivated N, waits for another record and new tasks. N's `not seen` is not a measured zero. N's binary is rebuilt and its hash in `builds.md` changes. A canary of another model, accepted before by a run that pins nothing, is now refused by every run, a resumed earlier stage included.
- **Neutral:** the $50 stop and the six figures are unchanged.
