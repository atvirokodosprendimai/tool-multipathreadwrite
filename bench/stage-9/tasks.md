# Stage 9: follow-on and control tasks, for the read in T3 S3

ADR-206 Decision 8. In each task the second change depends on the first: the first change defines a name, an import or a parameter, and the second change uses it. In a follow-on task the first change adds or removes lines above the second; in a control task it keeps the line count. Each reference patch is the upstream change itself, restricted to one file; read each instruction against `bench/tasks/<id>/reference.patch`.

The instructions state what to change and why, not which lines (Zy, 2026-11-20: *"rewrite for intent"*), follow-on and control alike, so the two classes differ in shape and not in wording. A spelled-out location hands the agent an anchor and makes a stale line number unlikely in either arm. Every instruction still pins what the oracle grades byte for byte and intent alone leaves open: a new name, a layout black would choose, a blank line. Checked on 2026-11-20 before any paid run: a fresh agent given only the instruction and the base file made all 24 results byte-identical to the reference result. It was told to put both changes in one plan, so that check says nothing about exposure.
