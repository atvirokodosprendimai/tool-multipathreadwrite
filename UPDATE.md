# Updating mrw

Choose the release you intend to use from
[GitHub releases](https://github.com/atvirokodosprendimai/tool-multipathreadwrite/releases)
or [Latest](https://github.com/atvirokodosprendimai/tool-multipathreadwrite/releases/latest).
Keep a benchmark's chosen binary and instructions pinned until its runs finish.

## Check the installation first

On a POSIX shell:

```sh
command -v mrw
mrw version
```

Replace the installation you actually invoke. Another binary can precede an updated one
on PATH. After upgrading, refresh any installed skill with `mrw --skill --dir DIR`;
updating the skill alone does not update the executable.

## Release assets and Homebrew

Download the asset for your OS and architecture using the [README install instructions](README.md#install).
Archives and `SHA256SUMS.txt` are published beside the raw binaries. Check the asset's checksum
against that manifest and confirm that `mrw version` reports the intended release tag.

For Homebrew, run `brew update && brew upgrade atvirokodosprendimai/tap/mrw`, then check
`"$(brew --prefix)/bin/mrw" version` and `command -v mrw`. The formula is generated by CI from
the release manifest (ADR-172).

Some builds append a Git revision to the version. If one is present, compare it with the
chosen release's commit. A missing revision alone does not identify an outdated binary:
the suffix depends on the VCS information Go recorded in that build.

## Go installations and local builds

A binary installed with `go install github.com/atvirokodosprendimai/tool-multipathreadwrite/cmd/mrw@<tag>`
reports the module version through `mrw version` unless the build has an explicit version stamp.
A pseudo-version identifies a commit rather than an exact release tag; no separate SHA is required.

An unstamped working-tree build normally reports `dev`, with a revision when available.
Building a checkout at a tag does not stamp that tag automatically. Use a published asset
when you need to reproduce the official release binary.

## Repairing a Homebrew tap update

A maintainer can run `gh workflow run brew-tap.yml -f tag=vX.Y.Z` without republishing assets.
The workflow requires that tag to be the latest stable release with successful release CI,
verifies the exact published formula, and makes no empty commit when repeated.

The changelog is the [release notes](https://github.com/atvirokodosprendimai/tool-multipathreadwrite/releases).
This file describes upgrades; [BESTPRACTICES.md](BESTPRACTICES.md) covers everyday use.
